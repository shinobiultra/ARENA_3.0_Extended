# Introduction


Activation patching and Shapley attribution answer different questions. In an
additive setting, a full-minus-ablated patch effect and a Shapley value can
agree exactly. In an interaction-heavy setting, the same patch effect can
overcount because every necessary component receives the whole interaction
effect when ablated alone.

This notebook uses exact coalition games to make that distinction concrete.
Later real-model work should compare SHAP-style token or feature attributions
against activation patching on matched clean/corrupt prompts.

The checked GPU preflight trains two finite CUDA model organisms. A linear
additive model verifies that exact Shapley values and full-minus-ablated
patching effects agree on real model outputs. A nonlinear neural coalition game
then verifies the interaction-heavy failure mode, where patching effects
disagree with Shapley and overcount absolute credit.


## Content & Learning Objectives

### 1. Agreement on additive controls

You will compare Shapley values to full-minus-ablated patch effects.

> ##### Learning Objectives
>
> * Treat activation patching effects as full value minus ablated value.
> * Verify additive games make patching and Shapley agree.
> * Check that both methods identify the same top feature.

### 2. Interaction overcount

You will document patching overcount on a pure interaction.

> ##### Learning Objectives
>
> * Compare Shapley totals with summed patching effects.
> * Explain why necessary components each receive full patching credit.
> * Report the failure mode instead of hiding it.

### 3. CUDA model-organism comparison

The verification path repeats the comparison on trained finite models.

> ##### Learning Objectives
>
> * Compare Shapley and patching effects from real model outputs.
> * Use an additive trained model as a positive agreement control.
> * Use an interaction-trained model as a disagreement control.

# Agreement on additive controls


### Exercise - compare SHAP and patching on an additive game

> ```yaml
> Difficulty: easy
> Importance: high
>
> You should spend up to 5 mins on this exercise.
> ```

In an additive game, ablating one feature removes exactly that feature's
contribution, so Shapley and patching agree.

```python
values = additive_game(t.tensor([1.0, 2.0, 0.5]))
report = shapley_patching_comparison_report(values, num_players=3)

utils.print_report("Additive SHAP vs patching", report.__dict__)

assert report.agrees_with_shapley
assert report.top_feature_agrees


def additive_agreement_smoke_test() -> dict:
    values = additive_game(t.tensor([1.0, 2.0, 0.5]))
    result = shapley_patching_comparison_report(values, num_players=3).__dict__.copy()
    result["shapley_values"] = result["shapley_values"].tolist()
    result["patching_effects"] = result["patching_effects"].tolist()
    return result


tests.test_additive_agreement_smoke_test(additive_agreement_smoke_test)
```

# Interaction overcount


### Exercise - document patching overcount on an AND game

> ```yaml
> Difficulty: medium
> Importance: high
>
> You should spend up to 10 mins on this exercise.
> ```

In a two-feature AND game, each feature is necessary. Full-minus-ablated patch
effects give each feature credit for the whole interaction, while Shapley splits
credit evenly.

```python
values = conjunction_game(2)
report = interaction_patching_failure_report(values, num_players=2)

utils.print_report("Interaction SHAP vs patching", report.__dict__)

assert report.documents_overcount
assert report.overcount == 1.0


def interaction_failure_smoke_test() -> dict:
    values = conjunction_game(2)
    result = interaction_patching_failure_report(values, num_players=2).__dict__.copy()
    result["shapley_values"] = result["shapley_values"].tolist()
    result["patching_effects"] = result["patching_effects"].tolist()
    return result


tests.test_interaction_failure_smoke_test(interaction_failure_smoke_test)
```

<details>
<summary>Expected output</summary>

```text
shapley_values: [0.5, 0.5]
patching_effects: [1.0, 1.0]
overcount: 1.0
All tests in `test_interaction_failure_smoke_test` passed!
```

</details>

<details>
<summary>Common bugs</summary>

- Hiding the disagreement because both features are necessary.
- Summing patching effects and calling the result total effect without checking overcount.
- Treating the interaction failure as a bug in Shapley rather than a difference in question.

</details>

<details>
<summary>Solution</summary>

```python
def interaction_failure_smoke_test() -> dict:
    values = conjunction_game(2)
    result = interaction_patching_failure_report(values, num_players=2).__dict__.copy()
    result["shapley_values"] = result["shapley_values"].tolist()
    result["patching_effects"] = result["patching_effects"].tolist()
    return result
```

</details>


This proves the comparison on real CUDA model outputs for a finite additive
model and a finite interaction model. It does not claim that activation patching
and SHAP are interchangeable in arbitrary transformer circuits.
