# Introduction


Input attribution asks which prompt tokens, features, or regions caused a model
output. Data attribution asks which training examples made this particular
trained model behave this way. That is a different causal question, so this
notebook keeps the target tiny and exact before discussing scalable in-run
approximations.

The toy problem trains a one-dimensional linear model for one gradient step.
Three training examples agree with the validation target; one example has a
flipped label. Exact Data Shapley should identify the flipped example as
harmful, Monte Carlo Data Shapley should converge toward the exact values, and
first-order in-run gradient-dot scores should point in the same direction.

The checked GPU preflight runs this as an actual CUDA one-step training update.
It enumerates every training-example coalition on GPU, computes exact and
Monte Carlo Data Shapley values, extracts per-example autograd gradient-dot
scores from the run, and checks that deleting the flipped-label example improves
validation utility.


## Content & Learning Objectives

### 1. Exact Data Shapley

You will compute exact training-example Shapley values.

> ##### Learning Objectives
>
> * Treat training examples as cooperative-game players.
> * Define utility as validation-loss improvement after training.
> * Verify a harmful example is negative under exact Data Shapley.

### 2. Monte Carlo Data Shapley

You will estimate Data Shapley from sampled training-example permutations.

> ##### Learning Objectives
>
> * Average marginal utility over random example orderings.
> * Compare sampled values to exact values on a tiny problem.
> * Keep harmful-example identification stable under sampling noise.

### 3. In-run first-order scores

You will compare exact Data Shapley to one-run gradient-dot scores.

> ##### Learning Objectives
>
> * Compute per-example training gradients and validation gradients.
> * Use first-order gradient similarity as an in-run proxy.
> * Check correlation with exact Data Shapley before scaling up.

### 4. CUDA one-step training preflight

The verification path runs the finite training problem on GPU end to end.

> ##### Learning Objectives
>
> * Compare exact coalition utilities to an actual optimizer update.
> * Validate Monte Carlo and in-run proxies against exact Data Shapley.
> * Use deletion of the harmful example as a behavioral control.

# Monte Carlo Data Shapley


### Exercise - approximate exact Data Shapley

> ```yaml
> Difficulty: medium
> Importance: high
>
> You should spend up to 10 mins on this exercise.
> ```

Monte Carlo Data Shapley samples example orderings instead of enumerating every
permutation.

```python
train_x, train_y, val_x, val_y = toy_data_shapley_problem()
report = monte_carlo_data_shapley_report(
    train_x,
    train_y,
    val_x,
    val_y,
    num_samples=512,
    seed=0,
)

utils.print_report("Monte Carlo Data Shapley", report.__dict__)

assert report.approximates_exact
assert report.harmful_example_matches


def monte_carlo_data_shapley_smoke_test() -> dict:
    train_x, train_y, val_x, val_y = toy_data_shapley_problem()
    result = monte_carlo_data_shapley_report(
        train_x,
        train_y,
        val_x,
        val_y,
        num_samples=512,
        seed=0,
    ).__dict__.copy()
    result["exact_values"] = result["exact_values"].tolist()
    result["sampled_values"] = result["sampled_values"].tolist()
    return result


tests.test_monte_carlo_data_shapley_smoke_test(monte_carlo_data_shapley_smoke_test)
```

<summary>Expected output</summary>


<summary>Common bugs</summary>

- Sampling coalitions rather than permutation marginal contributions.

- Reporting sampled values without comparing them to the exact tiny-game oracle.

</details>

# In-run first-order scores


### Exercise - compare in-run scores to exact values

> ```yaml
> Difficulty: medium
> Importance: high
>
> You should spend up to 10 mins on this exercise.
> ```

The in-run proxy uses per-example training gradients and validation gradients
from the same training run. On this toy problem, it should identify the same
harmful example and correlate with exact Data Shapley.

```python
train_x, train_y, val_x, val_y = toy_data_shapley_problem()
report = in_run_data_shapley_report(train_x, train_y, val_x, val_y)

utils.print_report("In-run Data Shapley proxy", report.__dict__)

assert report.identifies_harmful
assert report.correlates_with_exact


def in_run_data_shapley_smoke_test() -> dict:
    train_x, train_y, val_x, val_y = toy_data_shapley_problem()
    result = in_run_data_shapley_report(train_x, train_y, val_x, val_y).__dict__.copy()
    result["exact_values"] = result["exact_values"].tolist()
    result["in_run_scores"] = result["in_run_scores"].tolist()
    return result


tests.test_in_run_data_shapley_smoke_test(in_run_data_shapley_smoke_test)
```
