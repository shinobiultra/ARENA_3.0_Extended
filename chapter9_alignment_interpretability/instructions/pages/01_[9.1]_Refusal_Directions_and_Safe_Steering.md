# Introduction


Refusal-direction analysis asks whether a model has a direction in activation
space that separates refusal-like behavior from non-refusal behavior. Steering
then tests whether adding or removing that direction changes refusal behavior
without damaging general capability.

This section keeps the task safe and local. The toy exercises use synthetic
activations; the full experiment path uses sanitized meta-prompts plus the
public `josephmayo/refusal-compliance-pairs` refusal/compliance dataset. Do not
write or display harmful procedural prompt text for this exercise. The release
verification stores only aggregate metrics and prompt hashes; generated
completion text is not saved.

The verification contract is:

```text
direction separates refusal vs non-refusal prompts
steering changes refusal rate on safe benchmark
general capability degradation is small
random directions fail
```


## Content & Learning Objectives

### 1. Candidate refusal directions

You will compute a mean-difference refusal direction and compare it against
probe, SAE-feature, and Gemma Scope-style candidates.

> ##### Learning Objectives
>
> * Build a normalized refusal-minus-non-refusal direction.
> * Keep candidate direction methods comparable.
> * Avoid using unsafe prompt content in the direction dataset.

### 2. Separation checks

You will project activations onto a candidate direction and check whether the
scores separate refusal from non-refusal examples.

> ##### Learning Objectives
>
> * Use margin and accuracy, not only qualitative inspection.
> * Store refusal and non-refusal mean scores.
> * Treat failure to separate as a hard validation failure.

### 3. Safe steering effects

You will check whether steering changes refusal rate on a safe benchmark.

> ##### Learning Objectives
>
> * Measure refusal-rate change directly.
> * Test addition and removal directions separately in a full experiment.
> * Keep steering behavior scoped to benign benchmark examples.

### 4. Capability and random controls

You will bound general capability degradation and compare against random
directions.

> ##### Learning Objectives
>
> * Require small general capability degradation.
> * Use random-direction controls.
> * Reject steering claims that random directions match.

# Candidate refusal directions


### Exercise - compute a mean-difference direction

> ```yaml
> Difficulty: easy
> Importance: high
>
> You should spend up to 5 mins on this exercise.
> ```

A mean-difference direction points from non-refusal examples toward refusal
examples.

```python
refusal = t.tensor([[2.0, 0.0], [2.0, 1.0]])
non_refusal = t.tensor([[0.0, 0.0], [0.0, 1.0]])

direction = mean_difference_direction(refusal, non_refusal)

assert direction.tolist() == [1.0, 0.0]


def direction_smoke_test() -> list[float]:
    refusal = t.tensor([[2.0, 0.0], [2.0, 1.0]])
    non_refusal = t.tensor([[0.0, 0.0], [0.0, 1.0]])
    return mean_difference_direction(refusal, non_refusal).tolist()


tests.test_direction_smoke_test(direction_smoke_test)
```

# Full experiment path

The release verification for this section includes a CUDA-backed
`run_gpu_test` report in addition to the visible notebook checks below.

The full local experiment uses safe, benign data:

1. Build harmless allowed prompts and safe refusal-category labels.
2. Cache residual activations from a small instruction model.
3. Compute mean-difference, probe, SAE-feature, and Gemma Scope candidate directions.
4. Test separation on held-out benign prompts.
5. Add or remove the direction and measure safe refusal-rate changes.
6. Bound general capability degradation on ordinary benign tasks.
7. Compare against random and label-shuffled directions.

The GPU report also runs pinned real-model preflights plus a GT-2 aggregate
replication path. First, it runs a Pythia-70M-deduped safe-category hidden-state
preflight: final-token hidden states are extracted for sanitized category
descriptions, a mean-difference direction is learned on the first template
family, two held-out template families are evaluated, and random-direction plus
label-shuffle controls are checked. Second, it runs a Qwen2.5-0.5B-Instruct
safe instruction-model intervention preflight on the same 24 sanitized
meta-prompts. Finally, the GT-2 path uses the public refusal/compliance dataset:
it learns a Qwen refusal direction, checks held-out separation, layer and
position sweeps, PCA/SVD structure, random-direction and label-shuffle controls,
and measures aggregate-only behavioral completion changes under addition and
projection-out. Raw dataset prompts and generated completions are not stored.

