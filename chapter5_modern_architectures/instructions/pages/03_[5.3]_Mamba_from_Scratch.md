# Reading Material

You should understand the Chapter 1 transformer-from-scratch pattern before starting this
section. For Mamba, focus on the selective state-space recurrence, why input-dependent
`delta`, `B`, and `C` make the scan selective, and how a recurrent state replaces the
transformer's KV cache during generation. The important implementation invariant is
simple: recurrent, associative/parallel, chunked, and one-token cached paths should all
agree numerically.


# Introduction


Transformers route information with attention. Mamba-style models route information through a recurrent state whose update is data-dependent. This makes them a useful second architecture family for the frontier extension: they are not just "attention with different constants", and the interpretability questions change.

The key implementation object in this section is the selective scan:

```text
state_t = a_t * state_{t-1} + b_t
y_t     = C_t state_t + D u_t
```

where `a_t`, `b_t`, and `C_t` depend on the input. You will implement:

* a reference recurrent scan,
* an associative scan used as a parallel-style training path,
* a chunked recurrent scan for long sequences,
* causal depthwise convolution,
* a tiny Mamba block,
* recurrent-state inference for generation.

As with Gemma, the implementation exercises start with a tiny synthetic model. The verification path also loads a pinned Mamba-130M-HF checkpoint and verifies logits, deterministic generation, speed, and fast-kernel availability without claiming full weight-level parity to the didactic tiny implementation.

The ladder below is the core contract for this notebook. The simple recurrent
scan is the reference. Associative scan, chunked scan, block stepping, and
cached language-model inference are only accepted if they match that reference
within tight tolerances.

# Selective scan


### Exercise - build synthetic scan inputs

> ```yaml
> Difficulty: medium
> Importance: high
>
> You should spend up to 5-10 mins on this exercise.
> ```

The scan inputs mimic the tensors generated inside a Mamba block: `u` is the post-convolution stream, `delta` is a positive step size, `A_log` parameterizes stable state dynamics, and `B`, `C`, `D`, `z` are data-dependent scan/readout terms.

```python
def make_scan_inputs(seed: int = 0):
    t.manual_seed(seed)
    batch, seq, d_inner, d_state = 2, 7, 4, 3
    u = t.randn(batch, seq, d_inner)
    delta = t.rand(batch, seq, d_inner) + 0.1
    A_log = t.randn(d_inner, d_state) - 2.0
    B = t.randn(batch, seq, d_state)
    C = t.randn(batch, seq, d_state)
    D = t.randn(d_inner)
    z = t.randn(batch, seq, d_inner)
    return u, delta, A_log, B, C, D, z
```

> ```yaml

The associative scan composes recurrence transforms:

```text
(a2, b2) o (a1, b1) = (a2 * a1, a2 * b1 + b2)
```

This lets us compute the same recurrence with a parallel-style prefix scan.

Common bug: `A_log` parameterizes negative dynamics via `A = -exp(A_log)`. If you forget the minus sign, the discrete coefficient can exceed one and the recurrent state can explode.

<details><summary>Help - reading the recurrence</summary>

Think of each token as producing an affine transform of the previous state:
`state -> a_t * state + b_t`. The recurrent path applies these transforms in
order. The associative path composes the same transforms in a prefix-scan
schedule. If the composition rule is right, the outputs match.

</details>


### Exercise - verify chunked scan

> ```yaml
> Difficulty: medium
> Importance: high
>
> You should spend up to 10-15 mins on this exercise.
> ```

Chunked scan should match the full recurrent scan exactly up to floating point differences. This is the same state-carrying idea used for long-context inference.

Common bug: the first token in a new chunk must receive the final SSM state from the previous chunk; reinitializing the state to zeros at each chunk boundary breaks long-context equivalence.

<details><summary>Help - why chunking is a real correctness test</summary>

Chunking is not an optimization detail. It is the same state-carrying contract
that lets recurrent models process long streams without recomputing the whole
history. A chunked implementation that resets state can look fine on isolated
chunks while silently changing the model.

</details>

### Exercise - verify block recurrent-state parity

> ```yaml
> Difficulty: hard
> Importance: very high
>
> You should spend up to 20-30 mins on this exercise.
> ```

A Mamba block has two state caches:

* convolution state: the previous `d_conv - 1` projected tokens,
* SSM state: the recurrent selective-scan state.

Full-sequence block output should match one-token stepping when both states are carried correctly.

```python
t.manual_seed(0)
block = TinyMambaBlock(make_tiny_mamba_config())
hidden = t.randn(2, 5, block.config.d_model)

full, _ = block(hidden, use_cache=False)
state = block.initial_state(batch=2, device=hidden.device, dtype=hidden.dtype)
step_outputs = []
for pos in range(hidden.shape[1]):
    out, state = block.step(hidden[:, pos : pos + 1], state)
    step_outputs.append(out)
stepped = t.cat(step_outputs, dim=1)

assert t.allclose(full, stepped, atol=1e-5)


def block_step_equivalence_smoke_test() -> dict:
    t.manual_seed(0)
    block = TinyMambaBlock(make_tiny_mamba_config())
    hidden = t.randn(2, 5, block.config.d_model)
    full, _ = block(hidden, use_cache=False)
    state = block.initial_state(batch=2, device=hidden.device, dtype=hidden.dtype)
    step_outputs = []
    for pos in range(hidden.shape[1]):
        out, state = block.step(hidden[:, pos : pos + 1], state)
        step_outputs.append(out)
    stepped = t.cat(step_outputs, dim=1)
    diff = (full - stepped).abs()
    return {"max_abs_diff": diff.max().item(), "passed": bool(diff.max().item() <= 1e-5)}


tests.test_block_step_equivalence(block_step_equivalence_smoke_test)
```

<details><summary>Help - the two caches are different</summary>

The convolution cache stores the previous projected tokens needed by the
depthwise causal convolution. The SSM cache stores the recurrent state after the
selective scan. The full-sequence and step-by-step tests are designed to catch
mixing these two states or updating either state at the wrong time.

</details>

<details><summary>Help - why cache parity matters</summary>

For a recurrent architecture, generation should not need a transformer-style KV
cache, but it still has state. Full-sequence logits and one-token recurrent
logits matching within tolerance is the local proof that generation is using
the same computation as training-time forward passes.

# Full experiment path


For a full Mamba checkpoint exercise:

1. Load an official small Mamba checkpoint.
2. Map compatible weights into the local implementation, or compare directly against the official model.
3. Compare logits on fixed prompts.
4. Compare fixed greedy generation.
5. Report recurrent-state parity.
6. Report tokens/sec for full-sequence and recurrent generation paths.
7. Save checkpoint id, dtype, device, seed, prompt set, and peak VRAM.

```text
parallel_scan_output == recurrent_scan_output within tolerance
chunked_scan_output == recurrent_scan_output within tolerance
block step output == full block output within tolerance

peak VRAM is printed
```
