## A concrete new signature result

The [6.5 metric-repair CPU lab](../../mastery_hub/practice_addons/crosscoder_metric_repair/README.md) asks the learner to implement absolute Pearson correlation, rank AUC, TRAIN-only orientation fitting and frozen EVAL scoring. Its two-panel plot makes the bug visible: an exact copy scores 0.75/0.875 under the old mixed normalization for n=4/8 but 1 under Pearson. On a deliberately reversed EVAL relationship, the frozen TRAIN sign scores AUC 0 while an EVAL-refitted orientation misleadingly scores 1. Orthogonal/constant controls score 0 and shuffled ranks give AUC 0.5. Editable play changes the sample size, ties and train/eval relationship. A fresh CPU kernel executed 11 code cells including 12 tests in 1.019 seconds; [execution and figure hashes](../../.scratch/studiable-20261102/v1-quality/repairs/crosscoder_metric/execution.json) bind this deterministic teaching fixture. No crosscoder was trained, and the historical 6.5 model outputs remain preserved.

The lab explicitly defines zero for constant-column Pearson inputs; mathematically undefined correlation is not presented as a measured zero correlation. Pairwise AUC is quadratic and intended only for these tiny teaching fixtures.
