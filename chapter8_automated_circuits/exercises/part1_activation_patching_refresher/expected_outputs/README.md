# Expected Outputs for [8.1] Activation Patching Refresher

The signature result is the notebook-generated activation-patching panel, not
the verification report. For the exact two-hop copy model, denoising recovery
and noising damage both equal the planted three-cell route; off-route and
wrong-position donor scores are exactly zero.

## How this fixture was produced

The structural fixtures are maintained by
`scripts/generate_extension_verification_assets.py`. The exact toy output is
produced by `run_toy_signature_result` in `solutions.py`, and the secondary
real-model report is regenerated by
`scripts/run_extension_verification_reports.py --section 8.1`.

## Trusted implementation

The checked-in `solutions.py` is the trusted implementation. It starts from an
analytic model with a declared source-to-query-to-answer route, then runs the
pinned TransformerLens `gelu-1l` residual-position preflight separately. The
real-model result is mechanics evidence, not the learner-facing signature.

## Random seed

The exact model organism is deterministic. The real-model control uses the
pinned prompt pair and model revisions in `artifacts.lock.yml`; any random
control added later must record its local seed there.

## Allowed tolerances

Exact toy route, noising/denoising, and wrong-position checks require exact
equality. Tensor parity uses `rtol=1e-5` and `atol=1e-6`; CUDA acceptance
thresholds are declared in `artifacts.lock.yml`.

## When to regenerate

Regenerate after changing the planted route, patch metric, donor controls,
notebooks, instruction page, pinned model or tokenizer revisions, or report
infrastructure. Do not regenerate merely to hide a failing check.
