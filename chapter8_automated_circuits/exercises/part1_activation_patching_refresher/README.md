# [8.1] Activation Patching Refresher

This section teaches activation patching by making the learner rediscover a
known causal route before touching a real transformer.

The exact two-hop copy model moves a RED/BLUE source value through three cells:

```text
(embed, source) -> (route, query) -> (readout, answer)
```

The eight exercises implement the metric, normalization, transparent model,
single-cell intervention, denoising sweep, noising sweep, wrong-position donor
control, and localization report. The visible signature panel is generated by
the notebook from those implementations.

Expected exact result:

```text
top-k overlap                 1.0
route mean                    1.0
maximum off-route recovery    0.0
wrong-position donor maximum  0.0
denoising/noising max error   0.0
```

The pinned TransformerLens `gelu-1l` CUDA run remains a separate mechanics
preflight. It checks the real hook/device path but is not treated as circuit
discovery. `verification_report.json` is supporting evidence and must be
regenerated by the parent serialized GPU pass after learner-surface changes.

Files:

- `8.1_Activation_Patching_Refresher_exercises.ipynb`: learner notebook with
  visible implementations, semantic tests, dropdowns, controls, and play cell.
- `8.1_Activation_Patching_Refresher_solutions.ipynb`: fully inline solved
  notebook, executable without hidden taught methods.
- `solutions.py`: independent CPU oracle plus pinned CUDA preflight backend.
- `tests.py`: focused semantic, AST, and learner-contract regression tests.
- `expected_outputs/`: exact toy metrics and real-preflight acceptance bounds.
