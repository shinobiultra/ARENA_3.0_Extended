# Introduction


World-model interpretability claims should prove that a latent state predicts
something about the world, updates consistently under actions, and generalizes
to held-out states. For JEPA-style models, the first check is simpler: can the
context prediction match a held-out target embedding without reconstructing
pixels or tokens?

This notebook starts with tiny tensors. The full path applies the same checks to
I-JEPA, V-JEPA, VL-JEPA, toy Othello, mazes, Sudoku, RL world models, and
object-permanence setups. The release verification path also runs a pinned
V-JEPA 2 ViT-L frozen-latent preflight on generated synthetic videos. That
checks local CUDA loading, finite non-collapsed video features, a simple
same-object over different-object similarity control, a trained masked latent
predictor from occluded to visible states, held-out object-state probes over a
shuffled-label baseline, an action-conditioned latent rollout head over copy and
shuffled-action baselines, a synthetic late-occlusion object-permanence contrast,
and causal latent-token patching against same-size random-token patches. It is
still a generated-video control suite, not a real-video benchmark replication.


## Content & Learning Objectives

### 1. JEPA target prediction

You will check whether predicted target embeddings match the held-out target.

> ##### Learning Objectives
>
> * Evaluate JEPA predictions with cosine similarity and MSE.
> * Separate target-embedding prediction from reconstruction.
> * Require quantitative thresholds before interpreting latents.

### 2. Latent world-state probes

You will test whether a latent state predicts a held-out world label.

> ##### Learning Objectives
>
> * Fit or evaluate probes over world-state variables.
> * Treat Othello, maze, Sudoku, or RL state labels as held-out targets.
> * Reject probes that do not generalize.

### 3. Transition consistency

You will test whether state plus action delta predicts the next latent state.

> ##### Learning Objectives
>
> * Turn world-model dynamics into a vector-space check.
> * Evaluate action-conditioned state updates.
> * Separate state representation from transition representation.

### 4. Object permanence

You will test whether occluded objects remain represented more than absent
objects.

> ##### Learning Objectives
>
> * Compare visible, occluded, and absent object scores.
> * Require occluded evidence to remain above absent controls.
> * Treat object permanence as a falsifiable representation claim.

### 5. V-JEPA 2 feature extraction preflight

You will verify that a pinned real V-JEPA 2 checkpoint produces usable video
features before interpreting those features as a world model.

> ##### Learning Objectives
>
> * Load `facebook/vjepa2-vitl-fpc64-256` on CUDA with a pinned revision.
> * Check feature shape, finiteness, and nonzero variance.
> * Use a same-object versus different-object similarity control.
> * Compare visible, late-occluded, absent-occluder, and different-object videos.

# Full experiment path


The full local experiment uses a JEPA or world-model system:

1. Choose a model family: I-JEPA, V-JEPA, VL-JEPA, Othello, maze, Sudoku, or RL.
2. First verify real-model feature extraction on deterministic synthetic inputs.
3. Cache context, target, latent state, action, next-state, and object labels.
4. Test target-embedding prediction on held-out targets.
5. Probe latent states for held-out world variables.
6. Check action-conditioned transition consistency.
7. Compare visible, occluded, and absent object representations.
8. Add OOD layouts or rule variants before accepting a world-model claim.
9. Document what would make the world-model interpretation useless.

The checked GPU path for this notebook currently uses
`facebook/vjepa2-vitl-fpc64-256` revision
`b3c1679b7c34d3255ef3547f27c7b226aefab26f`. It first runs the five-video
feature-extraction sanity check, then runs a 200-video generated world-state
suite with base, next-state, occluded, and absent variants. V-JEPA itself stays
frozen; the report trains only small probes and prediction heads on the frozen
latents.

```python
def run_smoke_test(cpu: bool = True) -> dict:
```
