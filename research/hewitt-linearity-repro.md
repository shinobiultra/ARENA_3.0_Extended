## 1. Exact recipe

| Item | Value | Source |
|---|---|---|
| Models | Qwen3-1.7B, 4B, 8B, 14B (bf16 weights, frozen; steering vector fp32, cast to activation dtype when added) | Post; `steer/models.py` |
| Layer | block index `round(0.4*(n_layers-1))`, 0-indexed, output of the decoder block: **L11 for 1.7B** (28 layers; Qwen3-0.6B also has 28 layers, so also L11), L14 for 4B and 8B, L16 for 14B | Repo README; Post appendix; HF config |
| Positions | every position (prompt, response, and each generated token); hook adds `v` to the block output | `steer/hooks.py`, `steer/eval/generate.py` |
| Template | Qwen3 chat template, thinking off (`enable_thinking=False`) | `steer/models.py` |
| Exp 1 loss | `Σ_i [ NLL(D_i; α_i v) + λ Σ_{j≠i} KL(D_j; α_i v) ]`, λ = 0.2, α_i = softplus(u_i), init α = 1 / 3 / 5 / 7 for negative sentiment / French / code style / sycophancy | Post; `steer/methods/tuplesft.py` |
| Exp 2 loss | `NLL(D_i; s_i)` + 0.2·KL on the other two tasks, for `s_1=v1` (French), `s_2=v2` (negative sentiment), `s_3=v1+v2` (code style); no α | Post; `steer/methods/sumpair.py` |
| NLL | token mean over response tokens of the *chosen* response (the rejected text is not used by this loss) | `common.py`, `tuplesft.py` |
| KL | forward KL(π_steered ‖ π_unsteered), full vocabulary, token mean over response tokens of the other task's batch; summed over steer/task pairs, not averaged (tuple4: 4 NLL terms plus 12 KL terms per step) | `common.py`, `tuplesft.py` |
| Optimiser | Adam, **lr 0.02** (also for the u_i), grad-norm clip 1.0, `v` init 0 | configs; `tuplesft.py` |
| Steps | Exp 1: **1,200** (step-600 checkpoint saved, not evaluated); Exp 2: **600** (README/config; the post's Exp 2 caption does not state steps) | configs; README |
| Batch | **per-task batch per step: 8 for 1.7B** (model entry overrides `train.bs: 4`), 4 for 4B, 4×4 accumulation for 8B, 2×4 for 14B (so effective batch differs by model); `max_len` 512 | `configs/*.yaml`; `scripts/run_tuple.py` (`tcfg` override) |
| Seeds | one training seed (`seed: 0`); generation seed 0; one sample per prompt. Run-to-run variance is not measured. README gives SE about ±0.05 at n=100 and ±0.09 at n=30 for a score near 0.5 | README |
| Hardware used | one H100 80 GB; 8B and 14B use gradient checkpointing | README |

At 1.7B, 1,200 steps × 8 examples ≈ 9,600 examples per task from a 256-row train set, about 37 epochs (arithmetic from config and file counts). Per-task example counts are not stated in either post; the repo files are the only source. Forms: training outputs "generated by prompting a model", first GPT-6-Luna, later the target models themselves; the repo does not say which version it ships (the response style suggests Luna-generated, **[not established]**).

### Judge and metrics

- Config for all evals: `judge: {provider: openai, model: gpt-6-luna, temperature: 1, max_workers: 16, max_tokens: 2048}`. In `steer/llm.py` any model name starting `gpt-6` ignores the temperature and is called with `reasoning_effort="none"`, `max_completion_tokens>=2048`. Answers are cached on disk. The Post never names the judge; Forms names GPT-6-Luna for data generation and for the quality score.
- Generation for eval: 80 new tokens, temperature 0.7, top_p 1, multiplier 1.
- **Negative sentiment:** judge prompt "Rate how positive the tone of this chatbot reply is ... 1 = negative or flat, 10 = strongly upbeat", JSON `{"positivity": int}`; score = 1 − (p−1)/9. Prompt text: `steer/eval/behavior.py::SENTIMENT_POS_PROMPT`.
- **French:** fastText language ID (`facebook/fasttext-language-identification`), P(`fra_Latn`). No judge.
- **Code style:** regex detection of Google/NumPy/Sphinx section markers; macro-F1 one-vs-rest against the style the prompt's domain requires. No judge.
- **Sycophancy:** trivia items: judge labels the reply `user`/`correct`/`other`; score = 1 if it endorses the user's wrong answer (`SYC_ANSWER_PROMPT`). Feedback items: judge positivity, (p−1)/9 (`SYC_FEEDBACK_PROMPT`). README: validation has 25 trivia + 5 feedback and "the post reports `syc_answer_user` there"; the Post says "We eval just on the trivia". Which of the two the *test* table uses is ambiguous in the sources (**[not established]**).
- **Quality (not in the post's main tables):** judge coherence and relevance, 1–10, with a per-task "constraint" paragraph so the judge does not penalise the target behaviour (`steer/eval/quality.py`).
- Table entries are steered minus unsteered. "Crosstalk" = mean score change on the other tasks (signed mean, so negative leakage cancels positive; the repo's `--bleed` run stores the full vector × task matrix, but the post reports only the mean).

## 2. Which effects the post shows, and where

All numbers: Post, test set, "steered minus unsteered".

**Exp 1 (one direction, four norms), efficacy / crosstalk**

| Model | Efficacy | Crosstalk |
|---|---|---|
| 1.7B | +0.29 | +0.05 |
| 4B | +0.53 | +0.04 |
| 8B | +0.69 | +0.08 |
| 14B | +0.76 | +0.04 |

Per-task numbers are published only for 14B (neg. sentiment +0.60, French +0.83, code +0.78, sycophancy +0.84). **Per-task numbers at 1.7B are not in the post** (**[not established]**); they can be recomputed from the shipped checkpoint plus a judge. Strength at 1.7B: the effect exists (crosstalk stays near +0.05) but efficacy is about 0.4× the 14B value, so on average each behaviour is only weakly switched on; some individual tasks may be near zero, which the post does not show. Learned scales at 1.7B (appendix, L11): ‖v‖ = 24.5; α = 1.82 / 2.90 / 2.24 / 3.98 (neg. sent / French / code / syc), i.e. ‖α_i v‖ = 44.7 / 71.2 / 54.9 / 97.6. The text says α "tended to settle between 1 and 3", but the appendix has 3.98 (1.7B) and 0.86 and 1.16 (4B).

**Exp 2 (v1 French, v2 negative sentiment, v1+v2 code style)**, columns: efficacy of v1 / v2 / v1+v2, then crosstalk

| Model | French (v1) | Neg. sent. (v2) | Code (v1+v2) | Crosstalk |
|---|---|---|---|---|
| 1.7B | +0.85 | +0.55 | +0.45 | +0.00 |
| 4B | +0.91 | +0.57 | +0.48 | +0.01 |
| 8B | +0.94 | +0.62 | +0.86 | +0.05 |
| 14B | +0.93 | +0.62 | +0.92 | +0.04 |

(Column assignment from the post's header row.) At 1.7B the single-task vectors are strong, but the headline "the sum does a third task" reaches only +0.45 for code style, about half the 8B/14B value. Norms at 1.7B: ‖v1‖ = 46.2, ‖v2‖ = 43.7, ‖v1+v2‖ = 57.1, cos(v1,v2) = −0.19 (consistent with the law of cosines).

**0.6B:** the post has no result; the smallest model it reports is 1.7B. Whether either effect appears at 0.6B is **[not established]**; the efficacy trend with size makes a weaker effect the default expectation, which is an extrapolation, not a finding.

**Post's own caveats:** one model family, four tasks, gradient-descent vectors only; it argues linearity "should be tested, not assumed", and cites Smith (2024) that sometimes-linear directions are not ruled out by these constructions.

## 3. Cost at Qwen3-0.6B and 1.7B **[estimate]**

No measurement on a 5090 laptop exists in any source. This is a first-principles estimate; it should be calibrated with a 20-step timing run.

**Architecture (HF `config.json`):**

| | hidden | layers | heads/KV | MLP | vocab | tied emb | params |
|---|---|---|---|---|---|---|---|
| 0.6B | 1024 | 28 | 16/8 (head_dim 128) | 3072 | 151,936 | yes | ≈0.60B (0.44B non-embedding + 0.16B embedding) |
| 1.7B | 2048 | 28 | 16/8 | 6144 | 151,936 | yes | ≈1.72B (1.41B non-embedding + 0.31B embedding) |

bf16 weights: ≈1.2 GB (0.6B) and ≈3.4 GB (1.7B).

**Per-step work (tuple4).** For each of the 4 task batches: 1 steered pass for its own NLL, 3 steered passes for KL against the other α's, 1 unsteered reference pass. That is 16 steered forward+backward passes and 4 unsteered forwards per step. Weights are frozen, so backward needs only activation gradients through layers after the hook (L12–27) and the LM head. Sumpair is 9 steered passes and 3 unsteered forwards per step.

**VRAM.** Assumptions: bf16 weights; one graph alive at a time (each term is backpropagated immediately); the code materialises fp32 `[B, T, 151936]` logits, `log_softmax`, `exp` and the KL product, about 5 MB per token live (0.61 MB per fp32 vocab row × several copies, plus `log_q`); layer activations ≈ 78 KB/token/layer at 1.7B and ≈ 43 KB at 0.6B, only for layers 12–27; padded T ≈ 270–300 for the code batch (≈185 response tokens at ~4 chars/token plus prompt and template), ≈ 80–150 for the others.

| | bs 8, code batch (≈2,400 tokens) | bs 4 × 2 accumulation |
|---|---|---|
| 1.7B | ≈ 3.4 (weights) + 3 (activations) + 12 (logit tensors) ≈ **18–19 GB**; too tight on 24 GB with display and allocator overhead | ≈ 10–12 GB |
| 0.6B | ≈ 1.2 + 1.7 + 12 ≈ **15 GB** | ≈ 8 GB |

The vocabulary logits dominate, so 0.6B saves little VRAM at the same batch size. The repo already supports `grad_accum` in the per-model config. `model_cfg` raises `KeyError` for a model not listed, so 0.6B needs a new config entry (a few lines).

**Wall-clock** (assumptions: mean padded T ≈ 80 / 150 / 130 / 270 for sentiment / French / sycophancy / code, ≈5,000 tokens per step at bs 8; sustained 40–80 TFLOP/s bf16 for 1.7B, lower efficiency and launch-bound for 0.6B):

| Job | FLOP/step | 1.7B | 0.6B |
|---|---|---|---|
| Exp 1 tuple4, 1,200 steps | ≈130 TFLOP (1.7B), ≈46 TFLOP (0.6B) | ≈ 30–75 min | ≈ 12–30 min |
| Exp 2 sumpair, 600 steps | ≈81 TFLOP (1.7B), ≈29 TFLOP (0.6B) | ≈ 10–25 min | ≈ 4–10 min |

Evaluation generation (80 new tokens, HF `generate` with hooks, ≈25–35 ms per decode step at 1.7B): test split with `--bleed` is ≈1,600 generations for tuple4 (4 vectors × 4 tasks × 100) and ≈900 for sumpair, plus ≈400 unsteered; roughly 15–25 min total at 1.7B, about a quarter of that on validation (30 prompts). Judge calls for sentiment, sycophancy and quality are a few thousand short requests.

**No-training path.** The repo ships the trained vectors (about 1 MB total; README table with the exact paths) and `run_blog.sh` skips training when they exist, so a stress test of the 1.7B vectors needs only the Qwen3-1.7B download plus generation and scoring.

## 4. Judge-free or local-judge options

Only sentiment, sycophancy and quality use the LLM judge; French (fastText) and code style (regex) do not.
- `LLMClient` takes `base_url` and `api_key_env`, and `from_config` passes the `judge:` block as constructor arguments, so any OpenAI-compatible local server (e.g. vLLM) can be pointed at without code changes (non-`gpt-6` model names send `temperature` and `max_tokens` instead). The judge must run after generation, not alongside training, on a single 24 GB card.
- `provider: dummy` exists for plumbing tests only (random scores).
- **[suggestion]** Programmatic proxies: sycophancy trivia can be string-matched, since each row has `incorrect_answer`, `correct_answer` and `aliases`; sentiment can use a small local sentiment classifier; both then need a one-time check against the API judge.
- The French scorer's model is licensed CC-BY-NC-4.0 (see §6).

## 5. Controls the post does not report **[suggestions, not facts]**

Each is a candidate for the lab-design ticket; none is in the sources.

1. **Norm sweep of the published vector.** Fine grid of α from 0 to about 4× per behaviour at fixed `v`; plot all four efficacies plus quality against ‖αv‖. Shows whether behaviours occupy distinct norm windows, and whether the curve is monotone below α_i.
2. **Norm-matched random vectors** at each ‖α_i v‖ (and random directions drawn with the residual-stream covariance), scored on all four tasks. Separates "this direction" from "this much perturbation". 6.2 and 9.1 already teach this control.
3. **Off-distribution norms.** Compare ‖α_i v‖ (45–98 at 1.7B L11) with the per-token residual norm distribution at that layer, including the first-token / attention-sink positions. The checkpoints store `resid_norm` (a mean, "logged only"); the post does not report the ratio.
4. **Judge validity.** Hand-label about 50 outputs per task; test-retest at the judge's default settings; length confound (the post's example steered outputs are much shorter than the unsteered ones); compare with a local classifier; report quality alongside efficacy.
5. **Natural vs optimised direction.** (a) Freeze `v` = difference-of-means (the repo has `steer/methods/dom.py`) and learn only the four α's, to see whether the multi-norm behaviour needs an optimised direction; (b) train single-task vectors separately and report cos with the shared `v`; (c) for Exp 2, report the *untrained-for-it* sum: independently trained v1, v2 and what v1+v2 does without a t3 loss term. That is the baseline the LRH predicts.
6. **Strong vs weak LRH.** Report the full 4×4 vector × task matrix (unsigned), and the interaction `I = M(v1+v2) − M(v1) − M(v2) + M(0)` per metric on both probability and log-odds scales.
7. **Capacity / overfitting.** A d = 2048 vector with 4 scalars is asked to satisfy 4 targets; run a random-task-assignment control and report held-out (val) NLL against train, given ≈37 epochs on 256 examples.
8. **Seeds and intervals.** At least 3 training seeds (note `v` starts at 0, so seeds only change batch order), prompt-level bootstrap intervals, since SE is ±0.05 at n=100.
9. **Ablate the objective.** λ = 0 versus 0.2, to separate "single-task selectivity" from "KL regularisation pressure".
10. **Intervention form.** Layer sweep and last-position-only steering (the post fixes 40% and all positions); shifted prompts and multi-turn.

## 7. Connections to existing lessons

All pages read-only; paths under `/home/bitwise/Documents/ARENA_3.0_Extended/`.

- **Original 1.3.2 Function Vectors & Model Steering** (`chapter1_transformer_interp/instructions/pages/12_[1.3.2]_Function_Vectors_&_Model_Steering.md`): section 3 builds function vectors as sums of attention-head outputs, and section 4 reproduces Turner et al.'s activation addition on GPT2-XL with a scalar coefficient. These are the forward-pass "natural" vectors and coefficient-as-intensity convention the post attacks (the post cites Turner et al. 2023 for the LRH). Hewitt's `h + v` hook is the same operation with `v` trained by SGD. No composition (v1+v2) or norm-sweep exercise exists.
- **6.2 Gemma Scope & Feature Steering** (`chapter6_sparse_feature_methods/.../02_[6.2]_Gemma_Scope_and_Feature_Steering.md`): steering is `residual + coefficient * decoder_direction`; the lesson already states that a steering curve no stronger than a norm-matched random direction "fails the function claim" (line 174). Hewitt's Exp 1 is the counter-case to reading such a coefficient sweep as intensity of one feature.
- **9.1 Refusal Directions and Representation Engineering** (`chapter9_alignment_interpretability/.../01_[9.1]_Refusal_Directions_and_Representation_Engineering.md`): section 4 already searches for directions by gradient descent "with a regularising KL term" and tests them on held-out generations, the same estimator family as the post; sections 2 and 5 teach norm-matched random and label-shuffled dose-response controls, and "reading versus control can come apart". The sibling `01_[9.1]_Refusal_Directions_and_Safe_Steering.md` has persistent-hook generation exercises that cover the hook mechanics.
- **11.x** (`chapter11_representation_geometry/instructions/pages/`): 11.3 Causal Abstraction and DAS (learning an intervention subspace by optimisation, then trying to falsify it, "predictive vs causal objectives"); 11.4 Concept Erasure ("a guarantee can hold while information survives"); 11.1 geometry controls; 11.6 Feature Manifolds (cyclic, non-linear structure with linear read-out, the Engels et al. line the post cites as the weaker counterexample).
- **Micro-Lab ML05 in #239** ("Do two neurons cooperate, or did we just double the perturbation?"): defines `I = M(A+B) − M(A) − M(B) + M(0)`, matched-budget norms and probability-vs-log-odds scales. ML01 (units and norm-matched random controls) and ML03 ("try to make your result disappear") map to controls 2 and 5 above.

## 8. What this means for an afternoon lab

- **Smallest honest scope:** published 1.7B vectors (no training), a few hundred generations, French and code-style scores (no judge), plus a local sentiment/trivia proxy. Cost is the Qwen3-1.7B download plus generation, tens of minutes **[estimate]**. This is enough for the norm sweep, the norm-matched random control and the 4×4 matrix.
- **Retraining is realistic only at modest cost:** sumpair at 1.7B about 10–25 min and tuple4 about 30–75 min **[estimate]**, but the stock config's batch of 8 probably does not fit in 24 GB; use bs 4 with accumulation 2.
- **Do not promise a 0.6B replication.** The post has no 0.6B result and 1.7B is already the weak end (Exp 1 +0.29, Exp 2 sum +0.45).
- **Single-seed, n=100 results** carry ±0.05 noise; a lab that compares conditions needs seeds or bootstrap intervals.
- **Licensing blocks vendoring**, not reading or local running.
